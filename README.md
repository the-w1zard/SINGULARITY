Just as if you were using javascripts map or object.

> Where ever a disruptor could NOT be used, those areas had even more work put into them to make up for not being able to reach for one. Everything from creating hot caches, to redisigning entire architecures where they truly do not look like your average solution. The atom solution is a great example as roughly 90% of the required architecture was entirely avoided.

> [!NOTE] BUILDERS LOG #2
>
> Typically... I hide all the complexity and decision making in the underlying code itself in order to make our lives better. For example, hot paths / cold paths... the user doesn't even know about this on the light side since everything is done under the hood for them in the name of convenience. 
>
> That though, comes at a cost... here on the dark side... we do not give up ops, for any reason. When it comes to comps like the message queue or bus, in place of that underlying magic happening it is instead replaced with nested fns, for exmaple:
